# API以外の攻略情報の採用・更新ルール

この文書は、編成、代替キャラ、推奨スキル、オーバーロード、キューブなど、公開APIだけでは得られない攻略情報をアプリへ反映する際の共通ルールです。妻を含むアプリ利用者には収集・更新操作を求めません。

## 基本原則

- アプリ実行時に攻略サイトを巡回、スクレイピング、定期取得しません。開発時に確認した要約を静的TypeScriptデータとして同梱します。
- 有料プロキシ、アクセス制限の回避、ログインが必要な情報の無断取得、短時間の連続アクセス、本文・画像・表の丸ごと転載は行いません。
- 1サイトを常に正解とは扱いません。公式情報、企業攻略サイト、専門攻略サイト、更新が確認できるコミュニティ資料、具体的な実戦記録のある個人ブログを比較します。
- 出典URL、掲載元の更新日、アプリ側の確認日、採用理由を保持します。確認できない数値や代替を推測で補いません。
- 新キャラ、宝もの、スキル調整、新ボスなどメタへ影響する変更があった時に確認し、変更がない時はデータも更新しません。

## 信頼性の判定

1. 対象コンテンツ、キャラ、ゲーム版が現在の仕様と一致しているかを確認します。
2. 原則として直近1か月以内の更新を優先します。該当情報がなければ、条件と根拠が明確な最新の信頼できる資料を使います。
3. 複数の独立ソースで同じ内容が頻出するかを確認します。転載元と転載先、同じ表の引用は独立した2票に数えません。
4. 更新日だけで内容の薄い記事を優先せず、実戦条件、操作方法、対象ボス、投資段階、理由の具体性も比較します。
5. 意見が割れる場合は、用途、編成、操作、投資段階による違いを注記し、唯一の正解やクリア保証とは表現しません。

## 編成と代替キャラ

- 掲載元にある完成した5人編成を採用します。複数サイトから都合のよいメンバーを混ぜて独自編成を作りません。
- 同じ完成編成または同じ中核が複数ソースに頻出することを信頼性の補強に使います。
- 代替キャラは、掲載元が同じ枠の代替として明記している場合だけ収録します。アプリが所持状況から独自補完することはありません。
- 配置順が明記されていない場合は掲載順を推奨配置と断定しません。手動操作や特定ギミックなどの条件も併記します。

## 推奨スキル、オバロ、キューブ

- キャラ別に複数ソースを照合し、頻出する最終目標を採用します。実用到達点と最大投資が異なる場合は用途を分けます。
- オバロは「理想効果」「妥協・追加候補」「付けない効果」を分離します。妥協候補を必須目標として不足判定しません。
- 攻撃役は有利コードダメージ増加と攻撃力増加が頻出しても、支援役、最後の弾丸型、固定チャージ型などの例外へ一律に追加しません。
- 枠数、合計値、条件を混同しません。出典が本数を示す場合は枠数、特定しきい値を示す場合だけ合計％として登録します。
- 推奨なしはデータ欠落と区別し、「再厳選推奨なし」として扱います。未確認キャラへ一般論だけで推奨値を作りません。
- キューブは確認済みの候補名だけを表示し、根拠のない目標レベルは設定しません。

## 低負荷な確認手順

1. 新キャラ追加や攻略環境の変更を起点に、必要なページだけを1回ずつ確認します。
2. 一覧ページで比較できる場合は個別ページを全件巡回しません。大量並列取得や自動ポーリングは行いません。
3. 取得内容を共通のキャラIDへ対応付け、別衣装、宝もの、同名に近いキャラを名称の部分一致で統合しません。
4. 差分、出典、確認日をレビューし、テストと本番ビルド後に通常のGit手順で公開します。
5. 変更がない場合はコミットもデプロイも行いません。アプリ利用者の端末から攻略情報更新の通信は発生しません。

## 表示と権利への配慮

- アプリには結論の要約、短い理由、出典リンク、確認日だけを載せます。
- 攻略サイトの文章、画像、独自表をそのまま再配布しません。詳細は利用者が出典ページで確認できるようにします。
- 推奨値は公開情報の静的スナップショットであり、将来のアップデート後も正しいことを保証しません。
